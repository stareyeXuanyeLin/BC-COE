# COE-Echo-Mirror 变换渲染与持久化诊断

日期：2026-07-27
版本：1.8.1
BC：R130
测试素材：`ClothOuter/BusinessSuit`
相关控制台记录：`D:/agentData/佩拉的书桌/BC-Plugin/文档/控制台记录/26-7-27-7.md`

## 1. 当前现象

当前版本中，素材整体变换编辑控件表现为无效：

- 整体旋转无效；
- 整体缩放无效；
- 整体偏移 X/Y 无效；
- 设置数值后点击保存，再次打开方案时数值恢复为初始状态。

本轮已暂停继续测试，转入修复阶段。

## 2. 已确认的运行环境

控制台结果：

```json
{
  "pluginVersion": "1.8.1",
  "glVersion": "webgl2",
  "hasGLCanvas": true,
  "hasGLContext": true,
  "glDrawImageType": "function",
  "transformWrapped": false,
  "m4Type": "object"
}
```

结论：

- BC WebGL2 正常工作；
- WebGL Canvas 和 GL Context 均存在；
- `m4` 可用；
- 但最终的 `GLDrawImage` 没有被 COE 变换包装，`GLDrawImage._coeTransformWrapped === false`。

因此当前问题不是 WebGL 不可用，而是 COE 的 WebGL 变换包装没有安装到最终绘制函数上，或者安装后被其它脚本覆盖。

## 3. 变换渲染链诊断

插件的变换实现位于：

```text
src/07-renderer.js
installTransformRenderHooks()
```

安装条件：

```js
if (typeof GLDrawImage !== "function" || typeof m4 !== "object") return;
```

安装成功后才会执行：

```js
GLDrawImage._coeTransformWrapped = true;
```

当前运行时标志为 `false`，说明该安装没有生效。

### 3.1 `transformedCalls: 6` 的含义

临时探针得到：

```json
{
  "transformedCalls": 6
}
```

但每个绘制参数都是：

```json
{
  "OverallRotation": 0,
  "OverallScale": 1,
  "OverallOffsetX": 0,
  "OverallOffsetY": 0,
  "OverallCenterX": 50,
  "OverallCenterY": 50
}
```

这只能证明 CommonDraw 回调进入了当前 `GLDrawImage` 入口，不能证明 COE 的矩阵绘制已经生效。

由于 `transformWrapped` 为 `false`，当前入口是 BC 原始绘制函数，BC 不会消费以下自定义字段：

```text
Rotation
Scale
OverallRotation
OverallScale
OverallOffsetX
OverallOffsetY
OverallCenterX
OverallCenterY
```

### 3.2 矩阵分支没有执行

WebGL 探针结果：

```json
{
  "colorMaskDisabled": 0,
  "uniformUpdates": 154,
  "drawCalls": 154
}
```

COE 的自定义矩阵路径应该先执行：

```js
gl.colorMask(false, false, false, false);
```

因此正常情况下 `colorMaskDisabled` 应大于 0。当前为 0，说明 COE 的矩阵分支完全没有执行，所有绘制都走 BC 原始路径。

## 4. 第一主因：GLDrawImage 变换包装未安装

### 4.1 直接影响

当前即使编辑器能够正确写入：

```text
overallRotation
overallScale
overallOffsetX
overallOffsetY
```

画面仍然不会改变，因为最终的 `GLDrawImage` 没有执行 COE 矩阵变换。

### 4.2 可能原因

需要重点检查两种情况：

1. 插件初始化时 `GLDrawImage` 尚未就绪，`installTransformRenderHooks()` 提前返回，之后没有重试；
2. COE 安装成功后，BCX、LSCG、WCE 或其它插件重新赋值了 `GLDrawImage`，覆盖了 COE 包装。

当前初始化逻辑对变换包装失败没有日志，也没有独立的重试或覆盖检测。

### 4.3 修复方向

应让变换包装具备可恢复性：

- 安装前记录原始函数；
- 如果依赖未就绪，稍后重试；
- 每次绘制前或定时检查 `GLDrawImage._coeTransformWrapped`；
- 如果被覆盖，重新包装当前函数；
- 避免重复包装同一个函数；
- 记录安装失败、覆盖和恢复诊断。

最终运行时必须满足：

```js
GLDrawImage._coeTransformWrapped === true
```

## 5. 第二主因：整体变换输入没有写入 material

### 5.1 已完成的两次读取

编辑器输入后读取：

```json
{
  "materials": [
    {
      "id": "ms2fp0sv-x6lyjmf",
      "source": "ClothOuter/BusinessSuit"
    }
  ]
}
```

保存并重新进入启用方案后读取：

```json
{
  "materials": [
    {
      "id": "ms2fqxcx-gim7l2k:ms2fp0sv-x6lyjmf",
      "source": "ClothOuter/BusinessSuit"
    }
  ]
}
```

由于输出中没有：

```text
overallRotation
overallScale
overallOffsetX
overallOffsetY
```

这些字段实际都是 `undefined`，而不是显式的默认值 `0` 或 `1`。

### 5.2 当前断点

这说明数值在保存之前就没有写入：

```text
[data-overall-field] 输入框存在
→ input 事件没有将值写入 editing.materials 中的 material
→ saveEditing() 没有可保存的变换字段
→ 保存后自然恢复默认状态
```

因此当前证据不支持先把问题归因于服务器覆盖。需要先修复或验证输入监听。

### 5.3 相关代码

位置：

```text
src/10-editor.js
renderTransformEditor()
```

相关逻辑：

```js
host.querySelectorAll("[data-overall-field]").forEach(input =>
  input.addEventListener("input", () => {
    const field = input.dataset.overallField;
    let value = Number(input.value);
    if (!Number.isFinite(value)) return;

    if (field === "rotation") {
      value = clamp(value, -180, 180) * Math.PI / 180;
      setOptionalTransformValue(material, "overallRotation", value, 0);
    } else if (field === "scale") {
      value = clamp(value, 0.25, 3);
      setOptionalTransformValue(material, "overallScale", value, 1);
    } else if (field === "offsetX" || field === "offsetY") {
      value = clamp(value, -1200, 1200);
      setOptionalTransformValue(
        material,
        `overall${field[0].toUpperCase()}${field.slice(1)}`,
        value,
        0
      );
    }

    refreshPreviewLoop();
  })
);
```

需要验证：

- `data-overall-field` 输入框是否确实绑定了监听器；
- 监听器闭包中的 `material` 是否仍然属于当前 `editing.materials`；
- `refreshPreviewLoop()` 是否导致对象被替换；
- `CustomOutfitEditor.getCurrent()` 是否在编辑模式下读取同一个 `editing` 对象。

### 5.4 已知序列化逻辑没有遗漏字段

当前 `compactMaterialForStorage()` 已经包含：

```js
for (const key of [
  "overallRotation",
  "overallScale",
  "overallOffsetX",
  "overallOffsetY"
]) {
  if (typeof material[key] === "number") output[key] = material[key];
}
```

使用测试数据验证后，整体变换字段可以正常进入 compact storage。因此当前优先级是输入对象没有被修改，而不是 compact serializer 丢字段。

## 6. `formal-item-conflict` 诊断

控制台中大量出现：

```json
{
  "group": "ClothLower",
  "asset": "CrossSkirtLight",
  "stage": "buildSynthetic",
  "reason": "formal-item-conflict"
}
```

当前测试素材是：

```text
ClothOuter/BusinessSuit
formallyWorn: false
```

因此 `CrossSkirtLight` 冲突不是本次 BusinessSuit 变换无效的直接原因，但它暴露了编辑预览中的另一个问题。

相关代码：

```js
if ((character.Appearance || []).some(item => item?.Asset === sourceAsset))
  throw new Error("formal-item-conflict");
```

编辑器预览只保存了 Appearance 快照，没有真正隐藏可移除的正式服装。`src/04-assets.js` 中虽定义了：

```js
isEditorRemovableAsset(asset)
```

但目前没有使用。

### 修复方向

不能简单删除冲突判断，否则正式素材和 Synthetic 素材会重叠绘制。

正确方向是：

1. 编辑预览阶段隐藏可移除的同源正式素材；
2. 保留身体、头部等受保护素材；
3. 用 COE Synthetic 版本替代被隐藏的正式素材；
4. 关闭编辑器时恢复原始 Appearance。

另外，`formal-item-conflict` 当前会在每次刷新时重复追加，诊断记录应按：

```text
materialId + stage + reason
```

去重。

## 7. 整体中心算法问题，当前排在上述问题之后

位置：

```text
src/02-data.js
computeDefaultOverallCenter()
resolveCoordinatePipelineOffset()
```

当前整体中心算法仍未完整复现 BC 的 `CommonDrawComputeDrawingCoordinates()`：

- 使用了 `globalThis.PoseDef`，而 BC 当前使用 `PoseRecord`；
- `MovePosition` 是按素材组筛选的数组，当前实现没有按组筛选；
- `BodyStyle.DrawOffset` 是按 Group/Asset/Layer 匹配的数组，当前实现按普通对象处理；
- 未完整复现 `fixedYOffset`；
- 高度修正公式不完整。

该问题会造成中心偏移、旋转后漂移和不同姿势下结果不一致，但在 GLDrawImage 包装未安装之前，不是当前“完全无效”的第一原因。

### P0-1：恢复 GLDrawImage 变换包装

目标：

```js

### P0-3：验证保存链

编辑器 editing

→ localStorage

```

当前 `compactMaterialForStorage()` 已确认会保存这些字段。

### P1-1：修复编辑预览同源正式素材冲突

处理 `formal-item-conflict`，避免当前正式穿戴素材无法被编辑预览替代。

### P1-2：修复整体中心坐标管线

按 BC 当前 `CommonDrawComputeDrawingCoordinates()` 复现真实绘制坐标，或者在真实 CommonDraw 绘制阶段采集已经解析完成的 X/Y。

### P1-3：减少诊断噪声

对相同素材、阶段和错误去重，避免每帧重复追加相同的 `formal-item-conflict`。

## 9. 当前测试结论

Node 测试当前通过，但现有测试只验证了变换参数能否进入模拟的 `drawImage` 回调，没有覆盖：

- WebGL 包装是否成功安装；
- GLDrawImage 是否真的执行矩阵绘制；
- 输入框事件是否修改实际编辑对象；
- 编辑器保存后重新加载是否保持字段；
- 初始化竞态和其它插件覆盖；
- 正式 Appearance 冲突下的预览替代。

因此修复后需要补充运行时回归测试和至少一组真实 BC 页面测试。

## 10. 修复完成判定标准

### 运行时包装

```js
GLDrawImage._coeTransformWrapped === true
```

### 输入对象

在编辑器中设置：

```text
旋转：30
缩放：1.5
偏移 X：100
偏移 Y：50
```

随后 `getCurrent()` 应包含：

```json
{
  "overallRotation": 0.5235987755982988,
  "overallScale": 1.5,
  "overallOffsetX": 100,
  "overallOffsetY": 50
}
```

### WebGL 矩阵路径

变换绘制时：

```text
colorMaskDisabled > 0
```

且变换后的图像位置、角度和尺寸发生实际变化。

### 保存恢复

保存、关闭编辑器、重新打开同一方案后，四个整体变换字段仍保持非默认值。

### 正式素材冲突

当前编辑器预览中被选中的可移除正式素材不应再无条件产生：

```text
formal-item-conflict
```

除非该素材确实不可替代或无法安全隐藏。
